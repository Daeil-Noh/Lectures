# 「생성형AI 활용 실무」 슬라이드 교안 제작 가이드

동의대학교 인공지능학과 노대일 교수의 **2학년 학과 공통** 교과. 온라인 강좌, 주 3차시 영상 강의(한 차시 분량은 슬라이드 18~22장 정도 — **슬라이드에는 시간을 절대 적지 않는다**: 표지·오늘의 흐름·머리말 모두).
대상은 코딩 경험이 없는 학생. 코드는 다루지 않는다. **교안에서 「인문·상경계열」「비전공자」처럼 학생 계열을 가리키는 말은 쓰지 않는다** — “생성형AI를 직무에서 활용하는 방법을 배운다”로 표현한다. 강의에서 보여 준 예시를 학생이 생성형AI로 **그대로 따라 해 보는** 방식.

**먼저 `tools/LESSON_GUIDE.md`(자매 교과 가이드)를 끝까지 읽는다.** 파일 구조, 슬라이드 구성, 직접 해 보기, 점검 절차는 그 가이드를 그대로 따른다. 이 문서는 **다른 점만** 적는다.
기준 품질 = `ai-data-analysis/week01/lesson01~03.html/.js` (교수님이 승인한 1주차). 끝까지 읽고 구조·말투·밀도·인터랙션 수준을 맞춘다.

- 슬라이드 경로: CSS·JS는 `../../assets/...` (AI 교과와 동일).
- 수정 금지: `assets/*`, `ai-data-analysis/*`, `genai-practice/index.html`, `genai-practice/materials/*`, `tools/*`, `README.md`, `index.html`. 자기 주차 폴더 안에서만 작업. git commit 금지.

## 2. 도구 원칙 (중요)
- **기초·개념·안전 수칙·윤리**(1-1, 1-3, 2주, 13주 등): 특정 도구에 한정하지 않는다. "ChatGPT·Gemini·Claude 등 어떤 생성형AI에도" 통하는 내용으로.
- **시연·실습**: **Gemini(학교 Google 계정, Gemini Plus 제공)와 Claude(무료 버전)** 로 한다. 두 도구 모두에서 그대로 되는 과정을 보여 주고, 한쪽이 사용량 한도에 걸리면 다른 쪽으로 이어 하도록 안내.
  - 이미지 생성은 Gemini (Claude는 이미지를 생성하지 않는다).
  - 맞춤형 AI 비서: Gemini의 Gems, Claude의 프로젝트.
- 서비스 화면은 **직접 그리지 않는다**(로고·실제 UI 복제 금지). 채팅은 공통 `.chat` 모형(“화면은 단순화한 예시” 표기)으로. 메뉴 이름·버튼 위치·요금·한도·모델명처럼 자주 바뀌는 세부는 쓰지 않거나 “서비스 화면은 바뀔 수 있음”으로 일반화. 확신 없는 기능 단정 금지.
- 확인이 필요한 사실(서비스 기능, 법·제도, 통계)은 WebSearch/WebFetch로 확인하고 출처를 보고서에 남긴다. 숫자·사례는 출처가 없으면 쓰지 않는다.

## 3. 공통 부품 (assets 에 이미 있음)
- **프롬프트 상자**(복사 버튼 자동 동작) — 실습 차시마다 핵심 프롬프트를 이걸로 제시:
  ```html
  <div class="prompt"><div class="prompt-h">프롬프트<button class="copy" type="button">복사</button></div><pre>너는 <mark>[역할]</mark>이야. …</pre></div>
  ```
  `<mark>`는 학생이 바꿔 쓸 부분. 프롬프트는 실제로 붙여 넣어 쓸 수 있는 완성 문장으로.
- **채팅 모형**: `<div class="chat"><div class="chat-h">AI 채팅 (화면은 단순화한 예시)</div><div class="msg user">…</div><div class="msg ai">…</div></div>` (잘못된 답 예시는 `msg ai warn`)
- AI 답변 예시는 **미리 써 둔 예시**임을 표시(“예시 답변 — 실제 답은 매번 다를 수 있음”). 실제 서비스의 출력이라고 주장하지 않는다.
- 그 외 `.tile`, `.flow`, `.demo`, `.ctrl`, `.meter`, `.callout`, `.box`, `.q`(확인 문제), `.frag`(단계별 등장) 등은 AI 교과와 동일.

## 4. 직접 해 보기 (차시당 2개 이상, 손 아이콘)
코딩 대신 **판단·비교·조립**을 손으로 해 보게 한다. 예:
- 프롬프트 조립기(역할·맥락·지시·형식 토글 → 프롬프트 문장이 완성되고, 미리 써 둔 예시 답이 좋아짐)
- 같은 질문의 답 두 개 비교 카드, 환각 찾기 카드, 출처 신뢰도 점검표, 저작권 OK/주의/금지 판정 카드
- 매출표 조각을 보고 “AI에게 무엇을 물을지” 고르기, 차트 종류 고르기
- 페르소나 빌더, 카피 톤 슬라이더(예시 문장 전환), 스토리보드 칸 채우기, 반복 업무 점수 매기기(빈도×시간×규칙성)
결과 문구는 미리 계산/작성한 값. 데모 숫자는 node로 확인.

분기는 구조화된 출력으로

ROUTE = {'name': 'route', 'description': '요청을 분류한다.',
  'input_schema': {'type': 'object', 'properties': {
     'category': {'type': 'string',
        'enum': ['문헌', '실험계획', '행정', '기타']},
     'confidence': {'type': 'number'},
     'reason': {'type': 'string'}},
   'required': ['category', 'confidence', 'reason']}}

r = client.messages.create(model='claude-haiku-5-5',
      tools=[ROUTE], tool_choice={'type': 'tool', 'name': 'route'},
      max_tokens=300, messages=[{'role': 'user', 'content': req}])
cat = r.content[0].input['category']        # 언제나 네 값 중 하나
  • tool_choice로 도구를 강제하면 출력이 스키마를 따른다
  • enum으로 값의 범위를 막는다 → 코드가 안전하게 분기
  • confidence가 낮으면 사람에게 넘기기
  • 분류는 작은 모델로 충분한 경우가 많다
"모델이 다음에 누구를 부를지 정한다" 대신 "모델은 분류만, 다음은 코드가" — 워크플로 쪽으로 당겨서 예측 가능하게.

작성–검토 루프와 세 가지 멈춤 조건

draft = writer(task)
best = None
for rnd in range(MAX_ROUNDS):                 # ① 최대 횟수
    review = reviewer(task, draft, RUBRIC)    # 다른 컨텍스트
    if review['pass']:                        # ② 기준 통과
        break
    if best and review['score'] <= best['score']:
        break                                 # ③ 개선 없음
    best = review
    draft = writer(task, draft, review['feedback'])

무엇이 · 왜 · 어떻게 고칠지
세 조건 모두

같은 모델 계열의 검토자는 같은 맹점을 공유할 수 있다. 중요한 결과는 사람 표본 검토로 LLM 검토자 자체를 주기적으로 검증한다 (5회).

② 상태와 흐름 제어

흐름을 '상태 그래프'로 그려 두면

  • 노드 = 에이전트나 함수, 간선 = 다음에 갈 곳(조건 분기)
  • 모두가 읽고 쓰는 state 하나 — 공유 칠판을 구조화한 것
  • 단계마다 state를 저장(체크포인트)하면 실패한 곳부터 재개, 사람 승인 단계를 끼우기도 쉽다
LangGraph가 이 방식의 대표 프레임워크다. 직접 짠 코드도 이 그림으로 설명할 수 있어야 한다.
멀티 에이전트 시스템 구축 · 3회
체크포인트에서 재개하는 것은 Anthropic도 운영 과제로 꼽은 점(오류가 나면 처음부터 다시 하지 않고 이어서). 미니 프로젝트 보고서에 이 그림을 반드시 넣게 한다.

MCP: 도구를 꽂는 표준 단자

  • 서버가 도구(tools) · 자료(resources) · 프롬프트(prompts)를 내놓고
  • 호스트(AI 앱)가 클라이언트로 연결해 쓴다
  • 도구를 한 번 만들면 어느 에이전트에서나 같은 방식으로
Anthropic이 2024년 11월 공개, 2025년 12월 리눅스 재단 산하 Agentic AI Foundation(AAIF)에 기증해 중립 표준이 됐다.

MCP 서버, 열 줄

papers_server.py (공식 Python SDK의 FastMCP)

from mcp.server.fastmcp import FastMCP
import json
PAPERS = json.load(open('papers.json'))['papers']
mcp = FastMCP('lab-papers')

@mcp.tool()
def search_papers(query: str) -> list[dict]:
    """키워드로 가상 논문을 찾아 id·제목·연도를 돌려준다."""
    return [{'id': p['id'], 'title': p['title'], 'year': p['year']}
            for p in PAPERS if query in p['title'] + p['abstract']][:5]

if __name__ == '__main__':
    mcp.run()          # 표준 입출력(stdio)으로 서비스

상대시키는 대로 실행하는 함수스스로 판단하는 상대 — 능력을 '에이전트 카드'로 알림

한 조직 안의 리드 + 워커라면 A2A 없이 함수 호출로 충분하다. A2A는 조직 경계를 넘는 에이전트 협업(예: 공동 연구 기관의 에이전트에게 위임)에서 의미가 커진다.

같은 시스템을 Claude Agent SDK로

from claude_agent_sdk import (ClaudeSDKClient, ClaudeAgentOptions,
    AgentDefinition, tool, create_sdk_mcp_server)

@tool('search_papers', '키워드로 가상 논문을 찾는다', {'query': str})
async def search_papers(args):
    return {'content': [{'type': 'text', 'text': search(args['query'])}]}

papers = create_sdk_mcp_server(name='papers', version='1.0.0',
                               tools=[search_papers, read_paper])
options = ClaudeAgentOptions(
    system_prompt=LEAD_SYSTEM, model='claude-sonnet-5-5',
    mcp_servers={'papers': papers},
    allowed_tools=['Agent', 'mcp__papers__search_papers',
                   'mcp__papers__read_paper'],
    agents={'paper-scout': AgentDefinition(
        description='가상 문헌에서 한 계열의 방법을 조사할 때 쓴다',
        prompt=WORKER_SYSTEM, model='haiku',
        tools=['mcp__papers__search_papers', 'mcp__papers__read_paper'])},
    max_turns=20)
  • 루프 · 도구 실행 · 서브에이전트 띄우기는 SDK가 한다
  • 서브에이전트 정의 = description(언제 쓸지) + prompt + tools + model
  • 리드는 Agent 도구로 서브에이전트를 부른다
  • 직접 만든 도구도 MCP 서버 형태로 붙인다
2회의 코드 80줄이 설정 20줄이 된다. 대신 루프 안에서 일어나는 일은 덜 보인다 → hooks · 로그로 들여다본다.

직접 짤까, 프레임워크를 쓸까

직접 짜는 쪽
  • 논문에 쓸 실험: 구조를 정확히 통제 · 기술해야 한다
  • 호출 · 토큰을 하나하나 기록해야 한다
  • 새로운 협업 구조 자체가 연구 대상
프레임워크 쪽
  • 도구 · 셸 · 파일 · 권한을 다시 만들 이유가 없다
  • 체크포인트 · 재시도 · 추적이 필요하다
  • 연구실 사람들이 함께 유지보수한다

어느 쪽이든

① 흐름을 상태 그래프로 그릴 수 있고 ② 모든 호출의 기록이 남고 ③ 에이전트마다 도구 · 권한이 분리되어 있으면 된다. 2회에 프레임워크 없이 짠 코드를 들여다본 이유가 이것을 판단할 눈을 기르기 위해서다.

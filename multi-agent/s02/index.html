① 도구 사용 루프

메시지는 '내용 블록'의 목록이다

messages = [
  {'role': 'user', 'content': '예지보전 논문을 찾아 줘'},
  {'role': 'assistant', 'content': [
      {'type': 'text', 'text': '검색해 보겠습니다.'},
      {'type': 'tool_use', 'id': 'toolu_01', 'name': 'search_papers',
       'input': {'query': '예지보전'}},
  ]},
  {'role': 'user', 'content': [
      {'type': 'tool_result', 'tool_use_id': 'toolu_01',
       'content': 'P03, P07, P11'},
  ]},
]
text
일반 글
tool_use
모델이 "이 도구를 이 입력으로 실행해 달라"고 요청
tool_result
우리 코드가 실행 결과를 같은 id로 돌려줌 (role은 user)

Claude Messages API의 도구 사용 형식. 모델은 도구를 직접 실행하지 않는다 — 실행은 언제나 우리 코드(하네스)의 몫이다.

멀티 에이전트 시스템 구축 · 2회
가장 중요한 한 줄: 모델은 도구를 '요청'만 한다. 그래서 권한·검증·기록을 끼워 넣을 자리가 생긴다(하네스). tool_result를 user 역할로 보낸다는 점이 처음엔 어색하니 짚어 준다.

에이전트 루프, 열다섯 줄

def run_agent(system, task, tools, impl, max_turns=10):
    messages = [{'role': 'user', 'content': task}]
    for turn in range(max_turns):
        resp = client.messages.create(model=MODEL, max_tokens=2000,
            system=system, tools=tools, messages=messages)
        messages.append({'role': 'assistant', 'content': resp.content})
        if resp.stop_reason != 'tool_use':
            return text_of(resp), messages          # 끝
        results = []
        for b in resp.content:
            if b.type == 'tool_use':
                out = call_tool(impl, b.name, b.input)
                results.append({'type': 'tool_result',
                                'tool_use_id': b.id, **out})
        messages.append({'role': 'user', 'content': results})
    return '[중단] 최대 반복 횟수 초과', messages
  • impl: 도구 이름 → 파이썬 함수 사전
  • 모델 응답을 그대로 assistant 메시지로 붙인다
  • tool_result 는 한 메시지에 모아서
  • max_turns: 무한 루프 방지

① 도구 사용 루프

루프에 꼭 넣을 안전장치

def call_tool(impl, name, args):
    if name not in impl:                         # 없는 도구
        return {'content': f'알 수 없는 도구: {name}',
                'is_error': True}
    try:
        out = impl[name](**args)
        text = json.dumps(out, ensure_ascii=False)
        return {'content': text[:4000]}           # 너무 긴 결과 자르기
    except Exception as e:                       # 실패도 '결과'로 돌려준다
        return {'content': f'{type(e).__name__}: {e}',
                'is_error': True}
오류를 숨기지 않는다
is_error로 돌려주면 모델이 다른 방법을 시도한다
결과 길이 제한
긴 결과 하나가 컨텍스트를 다 잡아먹는다
횟수 · 예산 상한
max_turns, 누적 토큰 상한, 시간 제한
멀티 에이전트 시스템 구축 · 2회
멀티 에이전트에서는 이 상한들이 '에이전트 수만큼' 곱해진다. 워커 하나가 폭주하면 전체 비용이 튄다 → 워커마다 max_turns를 리드보다 작게 두는 것이 보통.

좋은 도구의 네 가지 조건

1 · 목적이 겹치지 않는다
search와 find가 둘 다 있으면 모델이 헷갈린다. 하나로 합치거나 차이를 설명에 쓴다.
2 · 결과는 짧고 다음 행동에 필요한 것만
검색은 id · 제목 · 연도만, 본문은 따로. 큰 결과는 요약하거나 쪽 나누기.
3 · 실패 메시지가 고칠 방법을 알려 준다
"P99 없음" 보다 "P99 없음. 있는 id: P01~P12"
4 · 위험한 일은 좁게
"아무 SQL 실행" 대신 "읽기 전용 질의". 쓰기 · 삭제는 따로 두고 승인을 받는다.

def delegate(objective, output_format, boundaries):
    brief = (f'목표: {objective}\n'
             f'출력 형식: {output_format}\n'
             f'하지 말 것: {boundaries}')
    report, _ = run_agent(WORKER_SYSTEM, brief,
                          tools=[SEARCH, READ],

③ 병렬과 합치기

한 응답 속 여러 tool_use → 동시에 실행

aclient = anthropic.AsyncAnthropic()

async def run_tools(blocks, impl):
    calls = [b for b in blocks if b.type == 'tool_use']
    outs = await asyncio.gather(*[           # 동시에
        acall_tool(impl, b.name, b.input) for b in calls])
    return [{'type': 'tool_result', 'tool_use_id': b.id, **o}
            for b, o in zip(calls, outs)]

# 루프 안에서
results = await run_tools(resp.content, impl)
  • 리드가 delegate 를 한 응답에 3번 부르면 워커 3개가 동시에 돈다
  • 리드 프롬프트에 "독립적인 조사는 한 번에 여러 개 맡겨라"
  • 워커 안에서도 검색 여러 개를 동시에 할 수 있다
리서치 시스템에서는 리드가 하위 에이전트 3~5개를 동시에, 하위 에이전트가 도구 3개 이상을 동시에 쓰게 바꾸자 복잡한 질의의 조사 시간이 최대 90% 줄었다.

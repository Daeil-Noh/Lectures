코딩 에이전트 환경은 일곱 겹

모델Opus · Sonnet · Haiku — 역할별로 다르게
하네스Claude Code — 루프 · 내장 도구 · 압축
규칙 파일CLAUDE.md · AGENTS.md — 저장소의 상식
서브에이전트.claude/agents/*.md — 역할 · 도구 · 모델
권한 · 훅.claude/settings.json — 막기 · 검사
MCP 서버.mcp.json — 문헌 DB · 실험 기록 등
CI · 자동화claude -p · GitHub Actions — 사람 없이

모두 저장소 안의 파일이다

→ git으로 버전 관리하고, 리뷰하고, 연구실 사람들이 같은 환경을 쓴다. 에이전트 설정도 연구 재현성의 일부다.

색칠한 세 층이 오늘의 중심. 하네스 엔지니어링 특강의 6부품(지침 · 도구 · 컨텍스트 · 권한 · 검증 · 기록)이 각 층에 흩어져 들어 있다.

CLAUDE.md (실습 템플릿에서 발췌)

# vibelab — 설비 진동 이상탐지 연구 코드

## 명령
- 테스트: python -m unittest -v
- 예제 실행: python -m vibelab.run data/sample_vibration.csv

## 규칙
- 표준 라이브러리만 쓴다 (설치 없이 돌아가야 함)
- 임계값은 '훈련 구간'으로만 정한다 (시험 구간 누설 금지)
- data/ 의 원본 파일은 수정 · 삭제하지 않는다
- 함수를 바꾸면 tests/ 에 테스트를 함께 추가한다

## 결정 기록
- 2026-11: 이상 점수는 z-점수, 기본 k = 3
  • 세션이 시작될 때 자동으로 읽힌다 → 매번 설명할 필요가 없다
  • 짧게. 명령 · 규칙 · 결정만. 긴 설명은 문서 링크로
  • AGENTS.md: 여러 코딩 에이전트가 함께 읽는 공통 규칙 파일 관례 (AAIF가 관리)
  • 3회의 결정 로그가 여기 산다
에이전트가 같은 실수를 두 번 하면 → 여기에 한 줄 추가. 하네스는 실패를 관찰하며 쌓아 가는 것.
멀티 에이전트 시스템 구축 · 4회
'시험 구간 누설 금지' 규칙은 템플릿 코드에 일부러 넣어 둔 버그와 연결된다(실습 6-1에서 리뷰어가 찾는지 본다). AGENTS.md는 OpenAI가 시작해 AAIF 출범 때 기증한 관례. 두 파일을 다 둘 때는 한쪽에서 다른 쪽을 가리키게 하면 중복이 없다.

② 쓰기 공간 나누기

  
git worktree: 한 저장소, 여러 작업 폴더

  

    

      
      

        
    
          
  • 폴더마다 다른 브랜치가 체크아웃된다 → 서로의 파일을 덮어쓰지 않는다
    • 
          
  • 기록(.git)은 하나라 합치기(merge)가 쉽다
    • 
          
  • 복제(clone)보다 가볍고 빠르다
    • 
        

        
나뉘지 않는 것
데이터베이스 · 포트 · GPU · 외부 파일 등 저장소 밖의 자원은 여전히 공유된다.

      

    

  

  
멀티 에이전트 시스템 구축 · 4회

  
경로 .claude/worktrees/<이름>과 브랜치 이름 worktree-<이름>은 Claude Code의 --worktree 기본값(문서 기준). 연구실에서 흔한 함정: 두 에이전트가 같은 GPU에 동시에 학습을 띄우거나 같은 결과 폴더(/data/results)에 쓰는 것 — worktree로는 안 막힌다.







  
② 쓰기 공간 나누기

  
병렬로 띄우는 세 가지 방법

  

    

      
① 터미널 여러 개
$ claude -w feature-peak
$ claude -w fix-threshold
사람이 세션마다 지시 · 확인. 가장 투명하다.

      
② 서브에이전트 격리
---
name: refactorer
tools: Read, Edit, Bash
isolation: worktree
---
메인 세션이 쓰기 작업을 맡기면 사본에서 일하고 브랜치로 돌려준다.

      
③ 직접 git 명령
$ git worktree add ../vl-fft -b fft
$ cd ../vl-fft && claude
어떤 에이전트 도구에서나 통하는 기본기.

    

    
끝나면: 각 브랜치를 사람이 리뷰 → main에 merge → git worktree remove. 변경이 없는 서브에이전트 worktree는 자동으로 정리된다.

  "permissions": {
    "allow": ["Bash(python -m unittest *)",
              "Bash(python -m vibelab.run *)",
              "Bash(git status)", "Bash(git diff *)"],
    "ask":   ["Bash(git push *)"],

    • 
          
  • Bash 통째 허용 대신 명령 단위로
    • 
          
  • 개인 설정은 settings.local.json (git에 안 올림)
    •

③ 가드레일과 자동화

  
훅: 도구를 쓰기 직전 · 직후에 내 코드를

  

    

      

        
.claude/hooks/guard_bash.py — PreToolUse(Bash)

        
import json, re, sys
cmd = json.load(sys.stdin)['tool_input'].get('command', '')
BLOCK = [r'\brm\s+-rf?\b', r'data/raw', r'git\s+push\s+.*--force']
for pat in BLOCK:
    if re.search(pat, cmd):
        print(f'차단: {pat} 에 걸림. 원본 데이터는 건드리지 말고 '
              '결과는 results/ 에 쓰세요.', file=sys.stderr)
        sys.exit(2)          # 2 = 막고, 이유를 에이전트에게 전달
sys.exit(0)

        
"hooks": { "PreToolUse": [{ "matcher": "Bash",
   "hooks": [{ "type": "command",
     "command": "python3 .claude/hooks/guard_bash.py" }] }] }

      

      

        
    
          
  • 입력: 표준 입력으로 JSON (도구 이름 · 입력)
    • 
          
  • 종료 코드 2 → 실행을 막고 stderr를 에이전트에게 보여 준다 → 에이전트가 방법을 바꾼다
    • 
          
  • PostToolUse: 파일을 고친 뒤 테스트 자동 실행 → 결과를 다시 알려 준다
    • 
          
  • 훅은 서브에이전트에도 똑같이 걸린다 — 여럿이 돌 때의 공통 안전망
    • 
        

        
규칙 파일(CLAUDE.md)은 부탁, 권한과 훅은 강제다.

하네스 특강의 '가이드(피드포워드)와 센서(피드백)'에 대응: 규칙 파일·권한 = 가이드, PostToolUse 테스트 = 센서. 정규식 차단은 우회될 수 있는 얕은 방어라는 점도 말해 둔다(5회 안전 — 다층 방어와 샌드박스).







  
③ 가드레일과 자동화

  
사람 없이 돌리기: claude -p

  

    

      

        
scripts/review_diff.sh — 커밋 전 자동 리뷰

        
git diff main...HEAD > /tmp/diff.txt
claude -p "$(cat .claude/review_prompt.md) $(cat /tmp/diff.txt)" \
  --allowedTools "Read,Grep,Glob" \
  --max-turns 8 \
  --output-format json \
  | jq -r '.result' > review.md

      

      

        
    
          
  • -p: 질문 하나 처리하고 끝 (대화 없음)
    • 
          
  • --allowedTools: 묻지 않고 쓸 도구 — 읽기 전용으로
    • 
          
  • --output-format json: 결과 · 비용 · 세션 id를 기계가 읽게
    • 
          
  • --max-turns, 비용 상한 옵션으로 폭주 방지
    • 
        

        
반복문으로 여러 번 부르면 병렬화 워크플로, GitHub Actions에 넣으면 PR마다 도는 리뷰어 에이전트.
